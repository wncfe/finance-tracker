# Задание локальному агенту

Перенеси мой личный трекер бюджета «По неделям» из ChatGPT Sites в МОЙ аккаунт Cloudflare. Нужен обычный веб-сайт с общей базой для телефона и ПК, без PWA. Сохрани визуальный стиль и поведение исходника. Выполни реализацию, проверки и деплой, а не только составь план. Не используй платные ресурсы и не включай платный тариф без моего отдельного согласия.

## Исходники и статус

`stable-frontend/` — рабочая опубликованная версия. `sync-draft/` — незавершённая заготовка синхронизации, не готовый проект. Не публикуй её вслепую. В ней полезны структура данных, облачный интерфейс, optimistic concurrency и SQL-схема. Проверь и исправь клиентскую синхронизацию перед использованием. `route.ts` содержит зависимости от ChatGPT Sites, которые на моём Cloudflare не работают. Убери их и реализуй полноценный Worker.

## Целевая архитектура

Cloudflare Workers + Static Assets + D1 (SQLite-совместимая база) + Wrangler. Для этого интерфейса не нужны Next/Vinext и зависимости ChatGPT Sites. Создай нативный проект с package.json, wrangler.jsonc, исходниками Worker, public/, миграциями D1, README и .gitignore. Читай актуальные официальные Cloudflare docs для конфигурации и команд. Не создавай новую D1 на каждом повторном деплое. При необходимости получи мою авторизацию через штатный wrangler login. Токены не записывай в исходники или логи.

## Доступ

Это личные финансовые данные. Доступ только мне. Предпочтительно Cloudflare Access с входом по одноразовому коду на email; уточни мой email для allowlist, когда понадобится. Защити production URL, API и возможные обходные workers.dev/preview URL. Используй документированную проверенную идентичность Access; если применяется JWT — проверяй подпись, issuer, audience и срок действия. Не доверяй произвольным заголовкам oai-authenticated-user-id/email или неподписанному email с клиента. Проверь актуальные возможности ctx.access в Workers; не переноси специфичную авторизацию ChatGPT. Не оставляй API записи публичным на время настройки. Если интерактивная настройка Access требует моего участия, подготовь всё остальное и дай точный короткий финальный шаг. Не объявляй проект готовым до проверки защиты.

## Логика бюджета

Начальное значение: ноябрь 2026, 80 000 ₽. Другие месяцы и суммы доступны. Недели с понедельника по воскресенье, первая/последняя могут быть короче. Месячный бюджет распределяется по числу дней. Сумма базовых недельных лимитов должна ТОЧНО совпадать с бюджетом: считай целыми копейками. Ноябрь 2026: 1; 2–8; 9–15; 16–22; 23–29; 30 ноября.

Ввод — ОБЩАЯ сумма трат за неделю, новая сумма заменяет старую. Закрытие недели переносит экономию или отрицательный перерасход в следующую. Будущие незакрытые недели показывают базу, без досрочного переноса. Закрытие последней недели не должно переносить деньги в другой месяц автоматически. Открытие прежней недели заново открывает её и последующие, сохраняя расходы.

## Синхронизация и надёжность

- Сервер — общая база для одного аккаунта на всех устройствах. Ключ пользователя получай из проверенной серверной идентичности.
- API загрузки и сохранения бюджета, строгая валидация формата, границ сумм, дат и длины недель. Секреты и идентичность не принимает от клиента.
- Атомарная проверка версии при записи. Устаревшая версия должна давать 409, а не перезаписывать новые данные.
- Отображай честные статусы: загрузка / сохранение / сохранено / нет сети / конфликт. При ошибке не показывай успешное сохранение.
- Локальный кэш и очередь изменений без сети. Не перезаписывай локальные несохранённые записи при загрузке с сервера. После возврата связи повтори сохранение или покажи конфликт.
- При конфликте предложи выбрать серверную или локальную версию, с возможностью скачать локальную копию до замены. Защити от гонок при наборе текста, быстром редактировании, перезагрузке и нескольких вкладках. Не смешивай кэш разных аккаунтов.
- Сохранение без потери последнего ввода: корректно фиксируй значение при клике на закрытие недели/импорт/переход, не требуй двойного клика из-за перерисовки.
- Сохрани экспорт/импорт JSON и по возможности прямую запись в локальный файл как дополнительный бэкап. На телефоне должен работать стандартный импорт/скачивание без File System Access API.
- Совместимость с JSON старого сайта: format="po-nedelyam", version=1, months["2026-11"]={budget:8000000,spent:[0,0,0,0,0,0],closed:0}. budget/spent в копейках. После импорта данные должны сохраняться в D1.
- После очистки браузера и повторного входа загрузи данные из D1. Данные не хранятся только в браузере.
- SQL через параметры; никаких CREATE TABLE на каждом API-запросе. Миграции отдельно. Проверка Origin/CSRF для записей, безопасные cache headers; сторонним сайтам CORS не разрешать.

## Проверки и результат

Проверь: арифметика копеек, короткие недели, отрицательный перенос, открытие недели заново, смена месяцев, импорт старого JSON и отклонение повреждённого. Проверь сервер: анонимный доступ запрещён, два пользователя изолированы, запись/чтение из D1, конфликт двух устройств и повтор после ошибки связи. Проверь клиента: данные после перезагрузки и на втором независимом браузере/сессии, не подменяй это повторным чтением localStorage в одной вкладке. В production не добавляй тестовые финансовые записи и не удаляй мои реальные данные.

Заверши деплой в мой Cloudflare и выдай конечный URL, краткие команды следующих обновлений, способ экспорта/восстановления данных и инструкции по миграциям. Перечисли оставшиеся непроверенные пункты честно. Домен покупать не нужно; используй workers.dev, если его можно безопасно закрыть Access.
