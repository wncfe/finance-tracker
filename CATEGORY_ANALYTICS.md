# Категории и аналитика расходов

Категории во всех формах выбора упорядочены по числу расходов за всю историю аккаунта (включая закрытые недели); равные частоты сохраняют стабильный порядок справочника. «Продукты» объединены с «Супермаркетами» миграцией 0004. Старое название принимается как совместимый входной псевдоним, но не отображается в справочнике. Персональные правила браузера перенастраиваются при чтении. Незавершённые запросы не переписываются: их ID и исходный payload сохраняются для безопасного повтора.

Повторное открытие недели удалено из интерфейса и расчётного API. Старый тип действия `reopen` отклоняется и не изменяет данные. Закрытые недели сохраняют запрет на добавление и удаление расходов.

У каждого расхода в истории месяца и в окне недели есть действие «Изменить категорию». Оно доступно в закрытой неделе. Действие API `recategorize` принимает только месяц, индекс недели, ID расхода и категорию: дополнительные финансовые поля отклоняются. Сумма, дата, описание, ID, лимиты, остатки, переносы и состояние недель остаются прежними. Категория меняется в существующей строке; квитанция запроса и ревизия защищают от повторов и конфликтов между вкладками.

Круговая диаграмма включает расходы всех доступных месяцев за выбранный период. Режимы: день, календарная неделя (понедельник–воскресенье), месяц и произвольный диапазон с включёнными началом и окончанием. Календарная неделя может пересекать границу месяца; это отличается от бюджетных недель, которые ограничены месяцем. Даты выбираются через существующий интерактивный календарь приложения. Легенда показывает суммы и доли; нажатие выделяет соответствующий сектор. Пустой или некорректный период не отображает устаревшую диаграмму. Изменение категории обновляет диаграмму после сохранения.

Локальная проверка на реальной копии: `python tools/preview_real.py`, адрес http://127.0.0.1:8002. Вход — логин и пароль соответствующего облачного аккаунта на момент бэкапа. Скрипт создаёт `data/preview-real.sqlite3` из проверенного снимка только при первом запуске и не перезаписывает её при повторном запуске. Изменения в просмотре не отправляются в облако. Бэкап, проверенный снимок и рабочая копия находятся вне Git.

Проверки: `npm test`, `npm run test:analytics`, `npm run test:parity`, `npm run test:worker` на локальной D1, `npm run test:browser`. Покрыты сохранность закрытых недель при смене категории, неверная категория/ID/неделя, запрет дополнительных полей и `reopen`, границы месяцев и годов, високосный февраль, диапазон из одного дня, обратный диапазон, пустая история, суммирование через границы месяцев, выбор произвольного периода в браузере, выделение сектора и отсутствие горизонтального переполнения на 320/390 px.

Изменения опубликованы в production вместе с нормализованным хранением 7 ноября 2026 года. Порядок миграции и проверки истории описан в NORMALIZATION.md.
