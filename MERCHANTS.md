# Магазины и сервисы

Справочник связывает новые расходы с магазинами, сохраняя исходное описание и категорию. Старые операции не привязываются автоматически. Общий каталог находится в `web/merchants.json`; персональные записи, синонимы и изменения общих названий хранятся отдельно для каждого аккаунта и синхронизируются между устройствами.

Совпадение выполняется по названию или явно добавленному варианту после нормализации регистра, пробелов и типографики. Подстроки и опечатки не сопоставляются автоматически: похожее название может быть показано как подсказка для ручного выбора. Если одному написанию соответствуют несколько магазинов, пользователь выбирает магазин вручную. Категорию магазин не задаёт. Скрытие исключает магазин из выбора, но сохраняет связи с существующими тратами. Редактирование записи меняет её отображаемое название у связанных операций, исходный текст траты не меняется.

Список «Магазины и сервисы» расположен в разделе «Бюджет» → «Данные». Магазин также можно создать во время добавления расхода. Персональные синонимы вводятся по одному на строку. Правила категорий по-прежнему независимы и хранятся в браузере.

История месяца позволяет отфильтровать расходы по магазину или показать расходы без привязки. Наименование магазина отображается рядом с категорией; старые расходы по-прежнему попадают в вариант «Без магазина».

## Обновление хранения

Миграция `cloudflare/migrations/0006_merchants.sql` добавляет необязательную ссылку на магазин и персональный справочник. До её применения в D1 новый Worker запускать нельзя; старый Worker также нельзя запускать после применения миграции, пока его запись расходов не проверена на совместимость. При выпуске нужен резервный снимок, режим обслуживания, применение миграции, развёртывание Worker и проверка результата. Этот документ не означает публикации изменений.

В объединённой версии миграция словаря идёт после `0005_remove_month_transfers.sql`. Серверная дата и запрет будущих расходов сохраняются. Аналитика учитывает связанные расходы по их фактическим суммам; связанные расходы группируются в привычки по магазину, остальные — по категории и нормализованному описанию.

Локальный сервер применяет миграцию при запуске. Тесты запускаются командами `python -m unittest discover -s tests -v`, `node tests/merchants.cjs`, `node tests/parity.mjs`, `node tests/merchant-browser.cjs` и `node tests/worker.mjs` (последний — только с локальным Worker и локальной D1). Браузерному тесту требуется Playwright с Chromium; путь к браузеру можно задать через `PLAYWRIGHT_BROWSERS_PATH`.

## Проверка словаря по выписке

Исходный файл содержит 1 158 строк с описанием и банковской категорией, без дат и сумм. Начальный каталог подобран после просмотра повторяющихся названий во всём файле, поэтому его проверка на этом же файле **не является независимой оценкой качества**. На всём файле однозначно совпали 529 строк; среди них нет строк с банковскими категориями «Переводы», «Пополнения» или «Наличные». Неизвестные имена не считаются ошибками и требуют выбора или создания записи. Для объективной оценки точности и полноты нужна новая, размеченная независимо выборка. Исходная банковская выписка не включена в репозиторий.
