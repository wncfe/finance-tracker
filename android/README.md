# Android-компаньон «По неделям» — 0.2.0

Нативный клиент Kotlin + Compose + Glance + WorkManager для Android 8+ (API 26), target SDK 35. Нажатие «+» открывает диалог Activity с клавиатурой. Браузер, WebView и PWA в этом сценарии не запускаются.

## Прямое сохранение

`кофе 250` сразу сохраняется в истории и учитывается в бюджете. Парсер работает в Worker: используются существующие `web/expense-parser.js`, словарь и история аккаунта. Парсер на Kotlin не дублируется. Локальные правила браузера пока не синхронизируются.

- Неизвестная категория → «Другое», её можно исправить в обычной истории.
- Отсутствующая/неоднозначная сумма, сомнительная дата или назначение вроде «перевод» → ошибка в нативной форме, текст остаётся для исправления.
- Несколько расходов разделяются `;`. Весь запрос сохраняется атомарно: ошибка в одной строке отменяет всю отправку.
- Проверки суммы, даты, категории, закрытых недель, авторизации и защита от дублей выполняются сервером.
- Сервер не может гарантировать правильное понимание произвольного текста: например, `кофе 250 350` означает сумму 250 350 рублей по правилам разделения тысяч. Для двух расходов нужны отдельные описания и `;`.

ID и точный текст сохраняются до сетевого запроса в зашифрованном хранилище. После тайм-аута повторяется тот же ID. Квитанция и финансовые строки сохраняются одной транзакцией с проверкой ревизии; конкурентные изменения повторно рассчитываются с актуальным бюджетом. Ошибка обновления виджета после успешной записи не запускает новое создание расхода.

Новая миграция для 0.2.0 не нужна. Таблица `companion_inbox` из 0008 теперь также хранит квитанции прямых отправок со статусом confirmed и исходным текстом. Ранее созданные pending-записи не сохраняются автоматически. Их можно обработать в настройках Android → «Ранее отправленные черновики». Явный API-параметр `mode: "draft"` сохранён для совместимости; Android его не использует.

## Установка и подключение

Готовый файл от корня репозитория: `data/releases/finance-companion-0.2.0-debug.apk`. Установите поверх версии 0.1.0: applicationId и debug-ключ сохранены, повторное подключение обычно не требуется. Рядом хранится SHA-256. Это debug APK для личной проверки; для распространения нужен собственный release-ключ.

1. В обновлённой PWA нажмите маленькую кнопку телефона в шапке → «Подключить устройство».
2. Введите HTTPS-адрес сервера и одноразовый код в Android-приложении. Код действует 10 минут и даёт доступ к аккаунту — передавайте его только своему устройству.
3. Добавьте виджет через меню рабочего стола.
4. Нажмите «+», введите `кофе 250`, нажмите Enter/«Добавить».

Токен действует 90 дней, отзывается в том же окне PWA. При обновлении токена используйте тот же аккаунт. Для смены аккаунта сначала проверьте историю и неопределённые отправки, затем удалите локальные данные через настройки приложения.

Токен, локальный ввод и финансовый кэш шифруются AES-GCM ключом Android Keystore. Пароли не хранятся. На сервере только SHA-256 токенов и кодов. Резервное копирование и перенос локальных данных отключены. После переустановки требуется новое подключение.

## Виджет

В 0.2.0 используется фактический размер через `SizeMode.Exact`: сумма центрирована, размер шрифта зависит от ширины и длины суммы. Внизу — расходы сегодня и круглая кнопка «+»; на широком размере появляются две категории. Постоянная дата синхронизации убрана. При ошибке отображается краткая отметка связи/авторизации, кэш сохраняется.

WorkManager обновляет данные при размещении, после отправки и примерно каждые 30 минут при наличии сети. Успешная отправка возвращает сводку для немедленного обновления кэша. Изменения через PWA попадут на виджет при очередной синхронизации; push нет. Xiaomi может задерживать фоновые задачи, а force-stop — приостановить их до ручного запуска. Дополнительные overlay-разрешения и постоянный сервис не нужны.

## Backend и проверки

Рабочий адрес: https://finance-tracker.alekseip2002.workers.dev. Версия с прямой отправкой опубликована 13 ноября 2026: Worker `1dbac857-88fc-4edc-8d38-2e8e3175a840`. Проверены production HTTP, точное содержимое JS и неизменность прежних финансовых записей/сумм. Локальный Python backend не реализует companion API. Схема D1 — миграция 0008; финансовая модель и аналитика используют прежние `apply()` и `financeWrites()`.

Маршруты `/api/companion/`: pair/exchange/devices/revoke для подключения; summary для виджета; submit для прямого сохранения; status/{id} для квитанции; inbox/review для старых черновиков. Bearer принимается только native-маршрутами, cookie — управлением устройствами и старыми черновиками. Bearer не даёт доступ к `/api/action` или `/api/state`.

`POST submit {operationId,text}` возвращает статус confirmed, items и summary. Повтор ID с другим текстом даёт 409; повтор старого pending-запроса возвращает pending без нового расхода. Суммы — целые копейки, даты — Asia/Yekaterinburg, текст до 4000 символов, до 50 расходов.

```powershell
npm run test:companion
npx wrangler dev --local --var REGISTRATION_CODE:local-test-invitation
# В другом терминале:
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/data/browsers"
npm run test:companion-browser
npm run test:worker
```

Проверены прямое сохранение и повтор ID, отсутствие частичного сохранения, неизвестная категория, конкурентные запросы, старые квитанции/черновики, изоляция аккаунтов, отзыв устройств, мобильное окно настроек и его закрытие, widths 320/390/1280. Kotlin/Glance скомпилированы, assembleDebug и lintDebug проходят, подпись и выравнивание APK проверены. Существующие unit/parity/parser/API проверки проходят. Общий старый browser.cjs по-прежнему содержит неоднозначный селектор фильтров истории.

Новый виджет ещё нужно визуально проверить в лаунчере Poco F5: 2×2/расширение, длинные суммы и системный шрифт, Enter и клавиатуру, авиарежим, закрытие во время отправки, перезагрузку и ограничения батареи. Аппаратный тест здесь не выполнялся.

Публикация: `npx wrangler deploy --dry-run`, затем `npx wrangler deploy`. Резервные копии и отчёты выпуска хранятся в игнорируемой `data/deployments/` и содержат приватные данные.
