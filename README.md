# По неделям

Самостоятельный трекер финансов. Без зависимости от ChatGPT и CDN.

## Запуск

Python 3.11+, без дополнительных зависимостей:

```powershell
python server.py
```

Открыть http://127.0.0.1:8000 и создать аккаунт (логин от 3 символов, пароль от 10). Данные каждого аккаунта сохраняются в SQLite `data/finance.sqlite3`, папка исключена из Git. Экспорт JSON и импорт в пустой аккаунт доступны в интерфейсе. Поддерживается старый формат: итоги недель импортируются отдельными записями. Данные старого сайта нужно экспортировать вручную.

## Бюджет

- Недели: понедельник–воскресенье, обрезаются границами месяца. Расчёты в целых копейках, распределение пропорционально дням.
- Нажатие недели открывает панель трат с суммой, категорией, датой и описанием. Закрытые недели доступны для просмотра.
- Ручной лимит перераспределяет бюджет между другими открытыми неделями. Закрытые лимиты сохраняются. Недостаток средств отклоняется.
- Закрытие распределяет остаток или перерасход на следующие открытые недели либо все остальные открытые недели месяца. Лимит закрываемой недели становится равен расходам. Если получателей нет, остаток остаётся в месяце для последующего переноса. Если перерасход превышает доступный бюджет, сначала увеличьте бюджет месяца.
- Из полностью закрытого предыдущего месяца можно перенести часть остатка. Исходные расходы не копируются; повторный перенос уже перенесённой суммы запрещён.
- История по месяцу и неделе, итоги категорий, защита от перезаписи изменений другой вкладки через ревизии.

## Проверки

```powershell
python -m unittest discover -s tests -v
node --check web/app.js
```

Браузерная проверка (Playwright нужен только для разработки):

```powershell
npm install
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/data/browsers"
npx playwright install chromium
node tests/browser.cjs
```

Отдельная тестовая БД, проверка входа, трат, перезагрузки, загрузки иконок, переполнения на 320/360/390 px. Скриншоты: `data/browser-test-*`. Проверка размеров Chromium не заменяет тестирование реальных iOS/Android.

## Будущий Cloudflare

Деплоя нет. `web/` — независимый интерфейс, `budget.py` — финансовая логика, `server.py` — локальный API/сессии/SQLite. Сервер слушает loopback. Встроенный HTTPServer предназначен для локальной разработки. Для Python-хостинга нужны production-сервер, HTTPS и `COOKIE_SECURE=1`.

Для Cloudflare Workers потребуется адаптировать API и сессии под Worker, а SQLite — под D1. HTTP-контракт и расчётные правила отделены от интерфейса. Текущий сервер нельзя просто загрузить в Pages как статику. Google OAuth, восстановление пароля и настройки production-регистрации отложены до хостинга.

`stable-frontend/`, `sync-draft/`, `AGENT_TASK.md` — исторические исходники и старое задание. Актуальная версия запускается командой выше. Старое задание на деплой не выполнять без новой команды пользователя.
