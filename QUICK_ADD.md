# Быстрое добавление расходов

Локальный запуск: `python server.py`, адрес http://127.0.0.1:8000. Локальные аккаунты и база SQLite отдельны от Cloudflare. Можно создать тестовый аккаунт кнопкой «Создать аккаунт»; пароль от 10 символов.

Кнопка «Добавить расход» доступна независимо от выбранного месяца. На телефоне она закреплена снизу. Введите текст, нажмите «Разобрать», проверьте строки и сохраните. Несколько расходов разделяются запятой, точкой с запятой или новой строкой. Запятая внутри числа сохраняется как десятичный разделитель.

Примеры:

- `кофе 250`
- `вчера такси 430`
- `позавчера купил раф за 350`
- `5 ноября магнит 1 250,50`
- `2026-10-31 продукты 850; 2026-11-02 кофе 250`

Без даты используется текущий день компьютера, без года — текущий год; результат виден до сохранения. Число вроде `12.05` без второй суммы неоднозначно: приложение требует уточнения. Неизвестные магазины требуют выбора категории. Неразобранные строки и исходный текст остаются в предпросмотре, их можно исправить или удалить. Возвраты, переводы, снятия и другие возможные нерасходные операции требуют явного уточнения назначения; доходы как сущность не добавлены.

Все строки сохраняются одной операцией с одной квитанцией. При ошибке любой строки не сохраняется весь набор. Сервер сам определяет месяц и неделю по дате. Закрытая неделя блокирует набор; быстрый ввод не открывает недели. Существующие расчёты лимитов, остатков и переноса между месяцами сохранены. SQL-миграций нет. Старые категории «Супермаркеты» и «Кафе» сохранены для совместимости, исторические расходы не меняются.

Сохранённые правила точного описания имеют приоритет над историей аккаунта, затем используется очищенный словарь из XLSX, затем общий словарь и осторожное сопоставление опечаток. У разных покупок в одном магазине могут быть разные описания и правила. «Мои правила категорий» позволяет изменить категорию или удалить соответствие. **Правила хранятся только в этом браузере, отдельно для каждого логина; между устройствами не синхронизируются.**

## Источники и проверка качества

`tools/analyze_expenses.py` читает предоставленный XLSX средствами стандартной библиотеки Python. Пользовательская категория приоритетнее банковской; категории выписки явно сопоставляются с категориями приложения. В файл `web/expense-history.js` включаются только очищенные названия торговцев и категории, без сумм, дат, телефонов и реквизитов. Приложение не загружает XLSX и не обращается к нейросетям или сторонним API.

Из 697 строк 210 исключены из построения/проверки словаря: переводы, наличные, кредиты, персональные описания, слишком общие названия или категории без уверенного сопоставления. Июль–сентябрь используются для построения правил: 100 названий, 97 однозначных соответствий. Октябрь–ноябрь — отложенная выборка: 123 операции. Конфликтующие названия не становятся однозначными правилами.

Проверка: `python tools/analyze_expenses.py`, затем `npm run test:parser`. Отложенная выборка и подробные результаты находятся в игнорируемом каталоге `data/expense-analysis/`.

| Показатель | Результат |
| --- | --- |
| Сумма | 121/123 — 98,4% |
| Дата | 123/123 — 100% |
| Категория, включая отказы | 105/123 — 85,4% |
| Категория среди 106 распознанных | 105/106 — 99,1% |
| Требуется ручное уточнение | 17/123 — 13,8% |
| Разделение нескольких расходов, отдельные синтетические сценарии | 3/3 |

Метрики получены на строках, сформированных из даты, описания и суммы выписки. Это проверка работы с реальными названиями, а не независимая оценка произвольной разговорной речи. Метки взяты из выписки с учётом пользовательских исправлений и не являются безусловной истиной. В проверочной выборке есть как знакомые, так и новые магазины; отдельная точность для полностью новых брендов не измерялась. Правила по ошибкам этой выборки не дополнялись.

Примеры ограничений: `Khochu Puri 4` содержит дополнительное число — сумма требует уточнения; «Самокат» требует контекста доставки или аренды; «Шмель», «Династия» и другие неизвестные бренды требуют категории. «Суши-Маркет» распознан как «Рестораны», тогда как метка выписки — «Фастфуд»: это одна ошибочная автоматическая категория. Неизвестный «Цветочный магазин» не подменяется догадкой по части слова.

Автотесты: 32 сценария парсера; Python-тесты расчётов/API, включая атомарность набора и запрет закрытой недели; сопоставление Python и Worker; клиентские повторы; браузерные проверки на 320/360/390 px и десктопе. Браузерные сценарии включают потерю ответа после записи и восстановление неподтверждённого набора после перезагрузки без дублей. Реальные iOS/Android отдельно не проверялись.

Дополнительная проверка перед релизом: `npm run test:edge` — 73 сценария парсинга и хранилища запросов, 36 сценариев валидации/атомарности с сопоставлением Python и Worker. `npm test` — 18 тестов расчётов и API. `npm run test:worker` проверяет настоящий Worker с отдельной локальной D1, включая набор через границу года, повтор квитанции и отсутствие частичных изменений при ошибке.

Покрыты нулевые/отрицательные/дробные/предельные суммы, обычный и Unicode-минус, неразрывные пробелы, валюты, числа в названиях, неверные и високосные даты, границы месяца/года, возвраты и переводы, пустой и неполный текст, несколько категорий, персональные правила, повреждённое/запрещённое хранилище и утрата ответов. В браузере также проверяются конфликт ревизий, устаревший предпросмотр, конфликтующие правила, экранирование HTML, ограничение 50 строк, отсутствие утечки окон календарей при повторном разборе и оформление выбора даты/категории. Исчерпывающего покрытия произвольной естественной речи нет: спорные записи требуют проверки пользователя.

## Что проверить вручную

1. Выберите другой месяц, затем добавьте `кофе 250`: дата должна остаться сегодняшней.
2. Введите несколько расходов и исправьте сумму, дату, описание и категорию в предпросмотре.
3. Введите неизвестный магазин и строку с несколькими суммами — сохранение требует уточнений.
4. Попробуйте дату закрытой недели: добавление заблокировано.
5. Сохраните правило категории, повторите описание, измените правило и удалите его.
6. Проверьте новые категории, иконки и удобство длинного списка на телефоне.
